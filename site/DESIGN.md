# terrakit.dbhq.uk - design

The reference is **midnight precision instrument**: Linear's register, which is
the one this product already has. Dark, exact, unhurried, nothing decorative.
The mark is two sheared parallelograms in ink and red, the wordmark is
JetBrains Mono, and the tool prints a ranked report to a terminal. The site
should look like the same object.

## The one structural decision

**Dark chrome, paper reading surface.**

This site exists for search. Its anchor page is a 2,800-word guide on `moved`
blocks, and the two guides together carry most of the value. Long-form reading
on a full-dark ground is measurably worse, so the site does not do it.

- **Ink**: the masthead, the hero, every block of captured output, and the
  footer. These are the moments that carry the brand, and the terminal samples
  are the strongest thing the site has to show.
- **Paper**: guide bodies, docs tables, anything a reader stays inside for
  more than a minute.

The join between the two is a hard edge, never a gradient. A gradient is a
decoration; an edge is a statement that two different things are happening.

## Palette

Nothing new. Everything is already in `tokens.css`, and the discipline is in
using less of it rather than adding more.

| Token | Use |
|---|---|
| `--ink` `#0B0E14` | chrome, hero, terminal blocks, footer |
| `--ink-text` `#D7DDE7` | body text on ink - `--text-2` and `--text-3` fail contrast there and must never appear on it |
| `--ink-line` `#1C222D` | hairlines inside ink |
| `--bg` `#FAFAFB` | the reading ground |
| `--text` `#101419` | reading text |
| `--blue` `#2B6BF3` | links and the single primary action, nowhere else |
| `--danger` `#D92D20` | critical findings only - never a heading, never a border, never decoration |

**Red is the product's one loud colour and it means exactly one thing: this
change can destroy something.** The moment it appears anywhere it does not
mean that, it stops meaning it in the output either.

## Type

- **Wordmark and all tool output**: JetBrains Mono, falling back through the
  platform mono stack. Never set prose in it.
- **Headings**: the same grotesk the rest of DBHQ uses, tight tracking at large
  sizes, no tracking games below 24px.
- **Body**: 18px minimum on guide pages, measure capped at 68 characters. The
  guides are the product here and they are read start to finish.
- **One weight step per level.** No page needs more than regular, medium and
  semibold.

## Terminal blocks

The captured output is the hero asset on every page. It is generated by running
the binary - never hand-written - and it is rendered as a terminal, not as a
quotation.

- Ink ground, `--ink-line` hairline, no drop shadow, no window chrome, no fake
  traffic lights. The output has its own authority and a macOS title bar
  borrows somebody else's.
- Severity colours inside a block match what the terminal actually prints. If
  the site shows `CRITICAL` in a red the binary does not use, the site is lying
  about the product in the one place it is claiming to be trustworthy.
- Never horizontally scrolling on desktop at the width it was captured. Capture
  narrower rather than letting the block scroll.

## Layout

- One column for guides. No sidebar, no table of contents floating alongside,
  no related-articles rail. A reader who arrived from a search for `terraform
  moved block` wants the answer, and everything beside the column is an
  invitation to leave before they get it.
- Generous vertical rhythm. The most common failure on a technical site is
  cramming, not sprawling.
- Section rules are hairlines, never boxes. Boxes suggest cards, cards suggest
  scanning, and these pages are read.

## Motion

Effectively none. A deterministic tool whose whole pitch is that it does not
guess should not have things sliding about. Transitions on interactive states
only, 120ms, no easing curve anyone would notice. Respect
`prefers-reduced-motion` and, more usefully, do not write anything that needs
it.

## What this design must never do

- No hero screenshot of a dashboard. There is no dashboard, and implying one
  misrepresents a CLI.
- No gradient mesh, no glow, no glass. The brand is an instrument.
- **No attribute value in any sample, anywhere on the site.** This is the
  tool's hardest contract and the site is bound by it too. Paths, addresses,
  counts and the tool's own sentences - nothing else.
- No capability shown that the shipped binary does not have. The twelve open
  issues are future work and must not appear as though they exist.
- No em dash, no en dash, anywhere, including in code comments.

## Why not full dark

It was the obvious move and it is the wrong one here. A dark landing page for a
terminal tool is the most predictable choice in developer marketing, and this
site's job is not to impress other tool authors - it is to be the best answer
on the internet for someone who has just watched Terraform threaten to destroy
a database they only meant to rename. That person is reading, at length,
possibly at speed, possibly at three in the morning. Give them paper.
